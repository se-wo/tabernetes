### Items

1. **The channel** (ND3, channel rule 1). Open one data channel `udp` to the page with `Ordered: false` and `MaxRetransmits: 0`, after the connection is connected. The settings come from one function, so a unit test can read them. With `DetachDataChannels()`, detach it. Each read gives one message: read into a buffer of 65,536 bytes. If the channel closes while the connection continues, write a log line and do not open it again.
2. **The header** (ND4, ND5, channel rules 2 and 3). An encoder and a parser of the 14 bytes, with the examination of rule 3 and the counted drops. The agent receives no credits: a credit is a drop. Use the two test vectors of 8.9.1. The codec is a copy of the codec of W5.1a in another Go module: the test vectors keep the two equal.
3. **Sends never wait** (ND12, channel rule 9). Read `BufferedAmount()` before each write; above 1,048,576 bytes, drop. `main.go` sets `EnableDataChannelBlockWrite(true)`: find out in the code of pion v4.2.26 if a write on a detached channel can still wait. If it can, write from one goroutine with a small queue and drop when the queue is full. Report what you found (Done item 5).
4. **The flow table** (ND15, ND18, ND19). A flow is one tab address and one pod address, with the time of the first datagram and of the last datagram in each direction. Use the timeouts of FL2 to FL4 (fact 16): 30 seconds, 120 seconds for a stream (answers, and a datagram 2 seconds or more after the first one). A timer removes closed flows. A tab address has one `tabPort` while it has flows; close it after its last flow.
   - `fromPod(src, dst, b)`: get or open the `tabPort` of `dst` (so that the answers of the tab side leave from the tab address, ND15), note the flow, send a datagram message with the source `src` and the destination `dst`.
   - A datagram message from the page (tab to pod, ND16): get or open the `tabPort` of the source, note the flow, `WriteTo(b, dst)`. The source can be a tab pod IP or the node IP of a tab node (the terminal, a `hostNetwork` pod): `openTabPort` then binds that node IP. A destination outside the flannel subnet of this node (`flannelSubnet`) is dropped.
   - Limits (channel rule 11): at most 4,096 flows and 1,024 `tabPort`s. Above the limit, a new flow or port is a counted drop.
   - `openTabPort == nil`, an error of `openTabPort` and an error of `WriteTo` drop the datagram with a counted log line. The agent must never panic here: between the merges of W5.2a and W5.2b, `openTabPort` is nil on `main`.
5. **No refusal** (channel rule 7). An ICMP error on a `tabPort` sends nothing to the page.
