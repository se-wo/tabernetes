### The API of W4.1 (fixed)

- `listenPodUDP(ctx context.Context, addr string) (*udpConn, error)`: the host mapping of rule 2 (`0.0.0.0`, the pod IP and `127.0.0.0/8` to the pod IP; a loopback row for `127.0.0.0/8`), port 0 from 32768, `errPortInUse` for an address in use, `EADDRNOTAVAIL` for another IP.
- `udpConn`: `ReadFrom(b) (int, net.Addr, error)`, `WriteTo(b, addr) (int, error)`, `Connect(netip.AddrPort) error` (the zero value removes the remote address), `LocalAddr`, `SetReadDeadline`, `Close`.
  - `WriteTo` never waits. A full queue of the receiver drops the datagram without an error.
  - After a refused datagram of a connected socket, the socket has one pending error. Exactly one call takes it: the next `ReadFrom` or `WriteTo` gives an error that wraps `syscall.ECONNREFUSED`. A `WriteTo` that takes it does not send its datagram.
  - More than `udpMaxDatagram` bytes give `errDatagramTooLarge`.
- The UDP table charges the time of `WriteTo` to the sender (AC1).

### Items

1. **Registration.** `wasiHandle` panics for a second handler of a type, and `tabnode_wasi_tcp.go` has the handlers of `bind`, `connect`, `credit` and `closed`. So:
   - In `tabnode_wasi_udp.go`, add the UDP handlers and two small routers, for example `byProtocol(tcp, udp wasiHandler)` (the field `protocol` of `bind` and `connect`) and `byUDPID(tcp, udp wasiHandler)` (an ID in `udpOf(p)` goes to UDP).
   - One ID has one protocol. A `bind` or `connect` with the protocol `tcp` for an ID of `udpOf(p)`, or with `udp` for an ID of `tcpOf(p)`, must not make a second socket with the same ID: answer `invalid-state` for `bind` (as a second bind), and do `p.Fail` for `connect`.
   - In the `init()` of `tabnode_wasi_tcp.go`, change only the four lines of `bind`, `connect`, `credit` and `closed` to use the routers. Remove the two `not-supported` branches of `tcpBind` and `tcpConnect`.
   - In the `init()` of `tabnode_wasi_udp.go`: `wasiHandle("datagram", timed(udpDatagram))` and `wasiOnClose("socket", ...)` (the closers are a list, so the TCP closer stays).
   - Keep the sockets of a peer in `p.State("udp", ...)`, as `tcpOf` does with `wasiTCPState`, and use the context `wasiPeerCtx(p)`.
2. **`bind`** (rule 2; UD2, UD3, UD20).
   - A second `bind` for the same ID gives `invalid-state`, as for TCP.
   - Use `tcpBindAddr` for the IP. Its errors are the same (`address-not-bindable`, MS3, no drop).
   - IPv6 `::` and `::1`: `bound` with a port, no socket in the table (rule 2). Use a counter for port 0, as `tcpV6Port` does.
   - Else `listenPodUDP(ctx, host:port)` with the host of the bind (`tcpListenHost` gives the host for `listenPod`; the same mapping applies). `errPortInUse` gives `address-in-use`.
   - Answer `bound` with the pod IP and the port (rule 3). After `bound`, each direction has a credit of 256 KiB of datagram bytes (rule 6). Start the read pump.
3. **`connect`** (rule 4). No answer for UDP: the Go side sends no `connected`.
   - A socket that is not bound: `p.Fail` (MS6, rule 1).
   - The address `0.0.0.0` or `::` with the port 0: `Connect(netip.AddrPort{})`.
   - Else `Connect` with the address and the port. An address of the wrong family or an IPv4-mapped address cannot come from a correct pod worker: `p.Fail`.
4. **`datagram` from the pod worker** (rules 5 and 6; UD14, MS4).
   - A socket that is not bound, or a TCP socket: `p.Fail` (MS6). A `data` for a UDP socket fails, also with 0 bytes (rule 1): `tcpData` returns early for 0 bytes (`tabnode_wasi_tcp.go`, line 724) before `connOf`; change it so that a UDP ID fails there. A `shutdown` for a UDP socket also fails: `connOf` of the TCP handlers already does `p.Fail` for an ID that `tcpOf` does not have; make sure that this stays true. `listen` for a UDP socket gets `listening` with `invalid-state` from `tcpListen` (rule 1).
   - More bytes than the credit of the pod worker: `p.Fail` (MS4).
   - More than 65,507 bytes cannot pass the examination of the contract (rule 5).
   - Put the datagram into the queue of the socket. A goroutine of the socket calls `WriteTo` for each datagram in sequence, then sends `credit` with the kind `datagram-bytes` and the size. The credit also goes back when `WriteTo` gives an error or the table drops the datagram.
   - The pending error has one path (rule 7): if `WriteTo` gives `ECONNREFUSED`, the datagram did not go. Send `error` with `connection-refused` one time, and give the credit back. The read pump does the same when `ReadFrom` takes the error. Each pending error gives exactly one `error` message.
5. **The read pump** (rules 3, 6 and 7; UD5, UD6, UD9, UD15).
   - A goroutine calls `ReadFrom` until the socket ends.
   - A datagram with not more bytes than the credit of the Go side: send `datagram` with the source address and port of `ReadFrom` (rule 3), and decrease the credit. Else drop it (UD6). Do not wait for credit: the queue of the socket is in the pod worker (rule 6).
   - `ECONNREFUSED`: send `error` with `connection-refused` (rule 7), one time for this pending error. The socket continues.
6. **`credit`** of the kind `datagram-bytes` adds to the credit of the Go side. Other kinds for a UDP socket: ignore them.
7. **`closed`** (rule 8): first send the datagrams that are still in the queue of the socket with `WriteTo` (Linux has already sent them when the program calls `close()`), as TCP rule 9 drains `data`. Then close the `udpConn` and release the ID. MS6 and the stop of the container (TCP rule 10, TC14) close at once, through `wasiOnClose`.
8. **AC1.** Charge the time of the handlers with `timed` (`tabnode_wasi_tcp.go`), and the time of the pumps off the event loop, as `tcpSockets.charge` and the TCP pumps do. The UDP table charges `WriteTo` itself: do not charge it a second time. Do not count the waits.
9. **MS2.** The dispatcher already examines the IDs. Add test cases for `datagram` and `credit` with a foreign socket ID.
