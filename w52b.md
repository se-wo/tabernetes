### Items

1. **nftables** (ND13). In `podLinkRules`, add UDP next to TCP, before `iifname "tabpods1" drop`: a `tproxy` rule for `meta l4proto udp` to port 15001 with the same mark, and the rule `socket transparent 1` also for UDP (only with nft_socket). Keep the rules without nft_socket working (`podLinkRules(false)`).
2. **The TPROXY socket** (ND13, ND14, `startUDPNet`). A UDP socket on `0.0.0.0:15001` with `IP_TRANSPARENT` and `IP_RECVORIGDSTADDR`. Read each datagram with its control message and take the original destination from `IP_ORIGDSTADDR`. Call `fromPod(src, origDst, b)`. Use a buffer of 65,536 bytes.
3. **The transparent sockets** (ND15, ND16, ND17, `openTabPort`). Make a UDP socket with `socketAs(podLinkUID, SOCK_DGRAM)` (ND17: the owner is uid 65534, so the rules of kube-network-policies examine its datagrams), set `IP_TRANSPARENT` and bind the tab address (a tab pod IP or a tab node IP) with its port. Do not `connect` it: two pods can share it. `WriteTo` sends to the pod (ND16). The answers of the tab side leave from this socket, so the Docker pod sees the tab address as the source (ND15).
   - Where a datagram of a pod arrives: for UDP, the `tproxy` statement finds only a connected socket, and a `tabPort` is not connected. So with the rule `socket transparent 1` (nft_socket) a datagram to a tab address arrives at the `tabPort`; without it, it arrives at the TPROXY socket with the tab address as the original destination. Both readers call `fromPod(src, tabAddress, b)`; the flow table does not care which socket read it (ND18).
   - A source outside 10.244.0.0/16 (a tab node IP) gets its answers only through the rule `socket transparent 1`, as for TCP. Without nft_socket, log it the same way as `setupPodLinkNet` does for TCP.
4. **Errors.** An error of the kernel on a socket (for example an ICMP error on a later read) sends nothing to the page (channel rule 7). Log the first error of each kind.
5. **IPv4 only**, as `dialTransparent`.
