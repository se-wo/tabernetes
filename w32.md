1. **One socket table for each pod worker.** `createPeer` allows one handler for each type. So make the table one time for each pod worker, for example `createSocketTable({ peer, io, idle })`.
   - It registers `peer.on` for `bound`, `listening`, `accepted`, `connected`, `data`, `credit`, `error`, `closed` and `addresses`.
   - It gives the IDs 1 to 0x7fffffff.
   - It routes each message by its socket ID or lookup ID.
   - `createSockets({ idle, io, table })` uses the table.
   - `runComponent` (the command world and the function of an entrypoint) passes the table.
   - `serveProxy` keeps `createSockets({ idle, pollableCreate })` with no table, the current stub (rule 12, PX15).
   - Keep `createIdle`, `nextTask`, `IDLE_LIMIT` and the stub results. The test "the stub gives the results of runwasi in the proxy world" must stay green.
2. **`TcpSocket`.** Implement the states of `wasi:sockets/tcp@0.2` (`tcp.wit`):
   - unbound, bind in progress, bound, listen in progress, listening;
   - connect in progress, connected;
   - closed.

   Error codes are thrown strings, as `fail` in `sockets.js` does.
   - `startBind` sends `bind`. `finishBind` throws `would-block` until `bound` arrives.
   - `startListen` sends `listen` with the backlog. Use the default of wasmtime (128), or the value of `setListenBacklogSize` within 1 to 4096 (`LIMITS.backlog`).
   - `startConnect` sends `connect`. It uses a new ID without a `bind`, else the bound ID.
   - `finishConnect` gives `[input-stream, output-stream]` after `connected`, or throws the error code of Go (rule 5).
   - Calls in the wrong state give `invalid-state` or `not-in-progress`, as in `tcp.wit`.
   - `subscribe()` gives a pollable that is ready when the answer arrives. Use `io.pollableCreate({ ready, wait })`, as `createStdin` (`component.js`) and `createHttp` (`http.js`) do. A message resolves the promise of `wait`, so `poll` suspends until a message arrives (CO19).
   - TC6: a socket of the family `ipv6` binds to `::`. It sends `bind` with the family `ipv6`.
   - TC20: these calls give `invalid-argument` with no message (fact 12):
     - a socket of the family `ipv6` that connects to an IPv4 address;
     - an IPv4-mapped IPv6 address;
     - an address of the wrong family in `bind`.
   - TC21: `setListenBacklogSize(0)` gives `invalid-argument`. The stub already does this.
   - Addresses of WASI: `{tag: "ipv4", val: {port, address: [a, b, c, d]}}` and `{tag: "ipv6", val: {port, flowInfo, address: [8 x u16], scopeId}}`. They change to the text forms of the messages and back.
3. **Addresses** (rule 2; TC5, TC17).
   - The local address of a bound socket is the IP of `bind` (`127.0.0.1`, `0.0.0.0` or the pod IP) with the port of `bound`.
   - The remote address of a connection that the component makes is always the address that the component gave to `connect`, for example a ClusterIP and its port. Go dials an endpoint behind a ClusterIP, but Linux gives the ClusterIP.
   - From `connected`, take only the local port. The local IP is `127.0.0.1` for a connection to `127.0.0.1`, else the IP of `connected`.
   - A connection that a listener on `127.0.0.1` accepted gives `127.0.0.1` at both ends, with the ports of `accepted`.
   - Each other accepted connection gives the addresses of `accepted`.
4. **`accept`** (rule 4). The `accepted` messages go into a queue of the listener.
   - `accept()` gives `[tcp-socket, input-stream, output-stream]`, or `would-block`.
   - After each accept, send `credit` with the kind `connections` and n = 1.
   - The pollable is ready when the queue has a connection.
5. **Streams** (rules 6 to 8; TC12, TC13, CO17). Use `io.inputStreamCreate` and `io.outputStreamCreate`, as `createHttp` does.
   - The input stream:
     - `read` and `skip` give the bytes of the `data` messages.
     - Send `credit` with the kind `bytes` for the bytes that the component took. You can send several together, for example at 64 KiB or when the buffer is empty.
     - `data` with 0 bytes is the end of the stream: after the bytes before it, a read gives `{tag: "closed"}`.
     - `error` gives `last-operation-failed` with `io.ioErrorCreate`.
     - Wrap `read` and `skip` with `idle.wrap(fn, (b) => b.byteLength > 0)`, as `blockStream` of `http.js` does (CO17).
     - `blockingRead` waits for a message.
   - The output stream:
     - `checkWrite` gives the credit that remains, up to 256 KiB, or 0.
     - `write` sends `data` of up to `LIMITS.data` and transfers the buffer. It decreases the credit. Never send more than the credit.
     - `credit` from Go increases the credit and makes the pollable ready.
     - `blockingWriteAndFlush` waits for credit.
     - `flush` does nothing.
     - Count `checkWrite` with `idle` when it gives 0.
   - `shutdown(receive | send | both)` sends `shutdown` (TC13). After `send`, writes give `closed`. After `receive`, reads give `closed`.
6. **The life of an ID** (rule 9).
   - `[Symbol.dispose]()` of `TcpSocket` sends `closed` if the ID is open. `http.js` uses the same hook. A drop of a stream does not close the socket.
   - The ID stays open after `bound` or `connected` with an error code. Send `closed` also for such a socket when it is dropped. A socket that never sent `bind` or `connect` has no ID and sends nothing.
   - When a listener is dropped, also send `closed` for each connection in its queue of `accepted`.
   - `closed` from Go can arrive in each state, also for an ID that you no longer know. For a known ID, mark the socket closed: each later call of the socket and of its streams fails. Do not send `closed` for this ID. For an unknown ID, ignore it.
   - Ignore all other messages for socket IDs that the table does not know. For `accepted` on a listener that is closed, send `closed` for the new ID.
   - `error` and the end of the stream do not end the ID.
7. **Name lookup** (rule 11). Change `resolveAddresses(network, name)`:
   - An IP literal gives a stream with this address and sends no message, as wasmtime does.
   - A name that is not correct gives `invalid-argument`. Examples: an empty name, a name of more than 253 characters (`LIMITS.hostname`), a character that is not in a hostname.
   - Each other name sends `lookup` with a new lookup ID. `resolveNextAddress()` throws `would-block` until `addresses` arrives. Then it gives one address for each call, then `undefined`.
   - An error code from Go (`name-unresolvable`, ...) is thrown by `resolveNextAddress`.
   - `subscribe()` is ready when `addresses` arrives.
   - `addresses` for a dropped stream is ignored.
8. **CO17 and CO19.** The functions of `COUNTED` keep `idle.wrap`. A call that gives data must reset the count. Give `wrap` a test function for the calls that succeed: `finishBind`, `finishListen`, `finishConnect`, `accept`, and `resolveNextAddress` with an address. In the stub, all calls count as "no data".
   - `ASYNC_IMPORTS` (`async_lists.js`) already includes all functions of `wasi:sockets` and the stream functions. Do not change it: it is part of the key of the transpile cache (decision 2).
   - `pollWithTask` (`component.js`) already continues through `nextTask`.
9. **TC22.** The options keep their values (`TCP_DEFAULTS`). W3.3a reports the defaults of runwasi, and W3.3b changes `TCP_DEFAULTS` if they are different. If the parent relays the values while you still run, you can apply them yourself and tell W3.3b in your report.
