1. **The table.** `createSocketTable` routes the types of its list by the socket ID. Add `"datagram"`. `closed` and `credit` already go through the table. One handler object for each ID, as `createTcp` does (`#handler`).
2. **`UdpSocket`.** Implement the states of `wasi:sockets/udp@0.2` (`udp.wit`): unbound, bind in progress, bound, and connected (bound with a remote address). Error codes are thrown strings, as for TCP.
   - `startBind` sends `bind` with the protocol `udp` and a new ID (`table.newID()`). `finishBind` throws `would-block` until `bound` arrives, then gives the error code of `bound` or the bound state. A second `startBind` gives `invalid-state`.
   - `checkAddress` (fact 12) examines each address of the component: the wrong family and an IPv4-mapped address give `invalid-argument` without a message. Multicast and broadcast give what W4.5a records on runwasi (fact 5), without a message.
   - In `stream` and `send`, the unspecified address (`0.0.0.0`, `::`) or the port 0 gives `invalid-argument` without a message (`udp.wit`; `startConnect` of TCP does the same, `sockets.js`, line 697). So the internal disconnect of rule 4 (`connect` to `0.0.0.0:0`) never comes from a component.
   - IPv6: a socket of the family `ipv6` binds to `::` or `::1` with the family `ipv6`. An IPv6 remote address in `stream` or `send` gives the code of W4.5a (expected `remote-unreachable`) without a message (rule 4).
   - `stream(remote)` (rule 4): on a socket that is not bound, `invalid-state`. With an address: send `connect` with the protocol `udp`, the address and the port, and do not wait. Without an address on a connected socket: send `connect` with `0.0.0.0` (`::` for `ipv6`) and the port 0. Give a new `[IncomingDatagramStream, OutgoingDatagramStream]`. Follow `udp.wit` and wasmtime for the streams of an earlier `stream` call.
   - `localAddress()`: the IP of `bind` with the port of `bound` (rule 3). `remoteAddress()`: the address of `stream`, or `invalid-state`.
   - `subscribe()` is ready when `bound` arrives, as for TCP (`io.pollableCreate({ ready, wait })`, `signal()`).
   - `[Symbol.dispose]()` sends `closed` for an ID that the Go side did not close (TCP rule 9). After `bound` with an error code, the ID is still open: send `closed` also then.
   - `closed` from the Go side: each later call of the socket and of its streams fails. Send no `closed` for this ID.
3. **`IncomingDatagramStream`** (rules 3, 6, 7).
   - `datagram` messages go into the queue of the socket. The Go side never sends more than the credit, so the queue has at most 256 KiB (UD5).
   - `receive(maxResults)` gives up to `maxResults` datagrams as `{ data, remoteAddress }`, or an empty list. Then it sends `credit` with the kind `datagram-bytes` for the bytes that the component took. You can send several credits together, but never keep more than 64 KiB.
   - The source address (rule 3): the address of the message; the pod IP shows as `127.0.0.1` for a socket that binds or connects to `127.0.0.0/8`. The pod IP comes from `bound`.
   - Rule 4: on a connected socket, a datagram from another source (it crossed the `connect`) is dropped in the pod worker, and its credit goes back at once.
   - `error` (rule 7): the next `receive` or `send` throws the code one time. A second `error` before that call does not add a second throw.
   - `subscribe()` is ready when the queue has a datagram or an error is pending.
4. **`OutgoingDatagramStream`** (rules 5 and 6).
   - The credit starts at 256 KiB (`LIMITS.credits`) after `bound`. `credit` messages of the kind `datagram-bytes` add to it.
   - `checkSend()` gives the number of datagrams of 65,507 bytes that the credit permits, and not more than the number of wasmtime (W4.5a records it). It gives 0 when the credit is less than 65,507 bytes.
   - `send(datagrams)`, for each datagram in sequence:
     - a datagram of more than 65,507 bytes (`LIMITS.datagram`) gives `datagram-too-large` without a message (UD14);
     - the remote address: required on a socket that is not connected; on a connected socket, none or the same address, else `invalid-argument` (`udp.wit`);
     - `checkAddress`, the unspecified address and port 0, and the IPv6 rule of item 2;
     - more datagrams than the last `checkSend` permitted: the result of wasmtime (`udp.wit`);
     - send `datagram` with the destination and the bytes (transfer the buffer), and decrease the credit.

     The result is the number of datagrams that went. An error on the first datagram throws; an error on a later one ends the list, as `udp.wit` says.
   - `subscribe()` is ready when `checkSend()` gives more than 0.
5. **Options** (the UDP part of TC22). `UDP_DEFAULTS` keeps the values; a set to 0 gives `invalid-argument`, as the stub does. W4.5a reports the defaults of runwasi and the values after a set (the minimum of the kernel, as `MIN_RECEIVE_BUFFER` for TCP). Apply them.
6. **CO17 and CO19.** `COUNTED.udp`, `COUNTED.incoming` and `COUNTED.outgoing` stay. Give `idle.wrap` a test function: `finishBind` without an error, `receive` with datagrams, and `checkSend` with more than 0 give data. An empty `receive` and `checkSend` of 0 count as calls without data. Do not change `ASYNC_IMPORTS` (`async_lists.js`): it is part of the key of the transpile cache (decision 2).
7. **The proxy world** keeps the stub (TCP rule 12, PX15): `createSockets` without a table. The test "the stub gives the results of runwasi in the proxy world" (`sockets.test.mjs`) must stay green.
