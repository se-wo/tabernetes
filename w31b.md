- `reservePort(proto, ip string, port int) (got int, release func(), err error)`, `portReserved(proto, ip string, port int) bool` and `errPortInUse`;
- `dialClusterFrom(ctx context.Context, addr string, localPort int) (net.Conn, error)`;

Until W3.1a is on main, put stubs with the same signatures into a test file of your own. Do not put them into the files of W3.1a.

1. **Registration.** In `init()`:
   - `wasiHandle` for `bind`, `listen`, `connect`, `data`, `credit`, `shutdown`, `closed` and `lookup`;
   - `wasiOnClose("socket", ...)` and `wasiOnClose("lookup", ...)`.

   Keep the sockets of a peer in `p.State("tcp", ...)` and use the context `wasiPeerCtx(p)`. Run the listeners, the dials and the read pumps in goroutines. The handlers must not block.
2. **`bind`** (rule 3; TC18, TC19, MS3, and TC6/TC7 on the Go side).
   - The address in the in-process network is the pod IP, also for `0.0.0.0` and `127.0.0.0/8`.
   - Reserve the port with `reservePort`. Port 0 gives an ephemeral port.
   - `errPortInUse` gives `address-in-use`. A listener has the address.
   - Each other IP gives `address-not-bindable`, with no drop.
   - IPv6 `::` and `::1` give `bound` with no reservation.
   - TC18: W3.3a records the result of runwasi for a second bind without a listener. If runwasi gives `address-in-use` there, also check `portReserved`. Until that fact arrives, implement rule 3 as written: `address-in-use` only with a listener.
3. **`listen`** (rule 4; TC1, TC7). Call `listenPod(ctx, host:port)`. It adds `policyListener` and the loopback row of `127.0.0.1`. Answer `listening`, or `address-in-use` for `errPortInUse`.
   - Accept up to the credit of connections. The first credit is the backlog.
   - Send `accepted` with `p.NewID("socket")` and the addresses of the in-process network.
   - For IPv6, answer `listening` and do not listen (TC7).
4. **`connect`** (rule 5; TC8 to TC11). Call `dialClusterFrom(ctx, addr, port)`, with the port of the `bind`, or 0. Give it a deadline of `synTimeout`. Answer `connected` with the addresses of the in-process network. The pod worker keeps the remote address that the component gave (rule 2).

   Map each error to its code in one function, for example `tcpErrorCode(err)`:
   - `ECONNREFUSED` (`refusedError`, the in-process network) gives `connection-refused` (TC4, TC11, TC15);
   - `os.ErrDeadlineExceeded` (`dropped` after `synTimeout`) gives `timeout` (TC10). This is not the `connection-refused` of CR8: wasi:sockets gives `ETIMEDOUT` as `timeout`;
   - `syscall.ETIMEDOUT` of the in-process network (a full queue at the end of the deadline, `net_fake.go`) also gives `timeout`;
   - an IPv6 address gives `remote-unreachable`. W3.3a confirms it on runwasi;
   - name each other code in a comment.
5. **`data` and `credit`** (rule 6; TC12, MS4).
   - The read pump reads from the connection only up to the credit. It sends `data` of up to 256 KiB (`wasiLimits["data"]`) and stops at credit 0.
   - Write the bytes of each `data` (`m.Bytes("bytes")`) in sequence in a goroutine, then send `credit`.
6. **MS4 from a handler.** The dispatcher closes an ID only when the examination of the contract fails. A `data` over the credit is a fact of the state, so add a helper to `wasiPeer` in `tabnode_wasi_msg.go`, for example `p.Fail(kind string, id uint32, reason string)`. It does the steps of the error path of `dispatch`: count the drop, log, run `wasiClosers`, and post `wasiCloseMsg`.
7. **`shutdown`** (rule 7; TC13 on the Go side).
   - `send`: `CloseWrite` after the pending writes. Use `interface{ CloseWrite() error }`.
   - `receive`: stop the read pump and discard the bytes. `trackedConn` has no `CloseRead`.
   - The end of the stream of the peer gives `data` with 0 bytes.
   - A reset gives `error` with `connection-reset` (rule 8).
8. **`closed`** (rule 9).
   - First write all pending `data` of the connection, then close it. The peer then gets the end of the stream, not a reset, as after `close()` on Linux. The echo server of `wasm-images/rust/echo` writes its answer and drops the stream at once (`src/main.rs`, lines 26 to 33).
   - Then release the reservation, the loopback row and the listener.
   - A `send` that fails for an ID that the container no longer owns: discard it with no log.
9. **The stop of the container** (rule 10, TC14). `wasiOnClose("socket")` closes everything of the ID. `startComponent` calls `peer.Close()` at the exit of the pod worker, and the context of the container ends.
10. **`lookup`** (rule 11; NL1 to NL3). Run it in a goroutine, because of `chargeDNS` and the locks.
    - First the names of the `/etc/hosts` of the pod, in the sequence of the file. `tabnode_ctr.go`, line 465, writes it: `localhost` gives `127.0.0.1` and `::1`, and the hostname gives the pod IP. W3.3a gives the sequence of runwasi.
    - Then `dnsLookup(ctx, name)` (`coreutils.go`): `clusterNamespace(ctx)` and the search path of `serviceProxy.lookup`, the resolver of `nslookup` (NL2).
    - Not found gives `name-unresolvable` (NL3).
    - At most 256 addresses.
11. **AC1 (TCP).** Charge the time of the handlers and the pumps to the container with `acctFrom(ctx).ChargeCPU`, off the event loop, as `tabnode_wasi_fetch.go` does. Do not count the waits.
12. **MS2.** The dispatcher already examines the IDs. Add test cases for `listen`, `data`, `credit`, `shutdown` and `closed` with a foreign socket ID.
